# ⚡ Deployer для macOS

[English](README.md) · **Українська** · [Русский](README.ru.md)

**Коміт, пуш і деплой ваших проєктів на власні сервери в один клік: нативний застосунок для macOS, без налаштування CI/CD і без FTP.**

Створено для соло-розробників, фрилансерів і **вайбкодерів**, які пишуть код із Claude Code, Cursor, Copilot або ChatGPT і хочуть просто й безпечно викласти його на сервер, не розбираючись у GitHub Actions, Jenkins чи Docker.

Якщо ви досі заливаєте папки через FileZilla і правите базу в phpMyAdmin, Deployer замінить це на повторюваний і безпечний процес:

> пишете код → **Коміт** → **Пуш** у Bitbucket / GitHub → **Деплой** на DEV → перевірка → **Деплой** на PROD

## Можливості

- **Коміт і пуш** з простого вікна: в один або кілька Git-сервісів одночасно (Bitbucket, GitHub, GitLab, Gitea / власний сервер).
- **Деплой в один клік** по SSH в окремі середовища (DEV, STAGE, PROD…), у кожного свій сервер, папка й гілка.
- **Попередній перегляд**: видно, які саме коміти й файли зміняться і які файли буде видалено.
- **Безпечний прод**: лише коміти, що вже є в `main`, і підтвердження введенням назви середовища.
- **Бекап бази даних** (`mysqldump`) перед кожним деплоєм, плюс команда після деплою для міграцій, очищення кешу, `composer install`…
- **Відкат**: деплой будь-якого попереднього коміту.
- **На сервер потрапляє лише те, що є в Git**: жодних випадкових локальних файлів, `.env` чи `.DS_Store` на проді.
- **Список «не чіпати»**: конфіги, завантаження й кеш на сервері не перезаписуються і не видаляються.
- **Секрети в Keychain macOS**: паролі SSH, ключів і БД ніколи не потрапляють у файл налаштувань.
- Підтримуються **SSH-ключі з паролем** і **вхід за паролем**; запит з'являється у вікні застосунку.
- **Один спільний Git-ключ** для всіх серверів: передається на сервер лише на час деплою і там не зберігається.
- **На сервер нічого не треба встановлювати**: достатньо SSH, `git` і `rsync`. Чудово працює з HestiaCP, хостингом із SSH, VPS, серверами Ubuntu / Debian.
- **Нативний застосунок macOS** з іконкою в Dock, меню й гарячими клавішами. Інтерфейс **англійською, українською та російською**.

## Як це працює

```
Mac (Deployer)                     Git-сервіс                     Сервер
──────────────                     ──────────                     ──────
Коміт ──► Пуш ───────────────────► Bitbucket / GitHub / …
Деплой ──► SSH ──────────────────────────────────────────────────► git fetch (з Git-сервісу)
                                                                   бекап БД → rsync у папку сайту
                                                                   → команда після деплою
```

## Завантажити

Завантажте останній **`Deployer-x.y.z-macOS.zip`** з [Releases](https://github.com/IRekunenko/Deployer---MacOS/releases/latest), розпакуйте й перенесіть **Deployer.app** у «Програми». Універсальна збірка: Apple Silicon та Intel.

- Deployer використовує системні `python3` і `git`, тому потрібні Xcode Command Line Tools: `xcode-select --install`.
- Застосунок не нотаризований Apple, тож macOS заблокує перший запуск. Відкрийте *Системні параметри → Конфіденційність і безпека* і натисніть **Все одно відкрити**, або виконайте:
  ```bash
  xattr -dr com.apple.quarantine /Applications/Deployer.app
  ```

## Вимоги

- macOS 12 або новіша
- Xcode Command Line Tools (`xcode-select --install`): дають `git`, `python3` і `swiftc`
- На сервері: доступ по SSH, `git`, `rsync` (і `mysqldump` для бекапів БД)

## Збирання з вихідного коду

```bash
git clone https://github.com/IRekunenko/Deployer---MacOS.git
cd Deployer---MacOS
./build_app.sh --install
```

Команда збирає `Deployer.app` і встановлює його в «Програми». Щоб оновити, запустіть її ще раз.
Без `--install` застосунок збирається в папку `dist/`.

## Швидкий старт

1. **⎇ Git**: перевірте ваші Git-сервіси (Bitbucket і GitHub уже додані; за потреби додайте GitLab або власний сервер). Створіть **спільний Git-ключ** і додайте його публічну частину в *Access keys* / *Deploy keys* репозиторіїв.
2. **🖥 Сервери**: додайте сервер (IP, порт, користувач) і виберіть SSH-ключ або вхід за логіном і паролем. Додайте публічний ключ Мака на сервер (наприклад, HestiaCP: *користувач → SSH Keys*). Натисніть **Перевірити підключення**.
3. **＋ Проєкт**: виберіть локальну папку проєкту, позначте, у які репозиторії пушити і звідки сервер забирає код, налаштуйте середовища (сервер, папка сайту, гілка, файли «не чіпати», за бажанням БД).
4. Користуйтеся кнопками **Коміт**, **Пуш**, **Перевірити**, **Що зміниться?** і **🚀 Деплой**.

> Перед першим деплоєм натисніть **Що зміниться?** і перегляньте список видалень: усе, що є тільки на сервері (конфіги, завантаження, кеш…), треба додати в «Не чіпати на сервері».

## Безпека

- Паролі зберігаються **лише в Keychain macOS**. У файлі налаштувань секретів немає.
- Секрети передаються на сервер через stdin SSH-сесії, а не в командному рядку, тож їх не видно в списку процесів сервера. Тимчасові файли створюються з правами `600` і видаляються після завершення.
- Локальний веб-інтерфейс слухає лише `127.0.0.1` і відхиляє запити з інших сайтів.
- Для спільного Git-ключа використовуйте *Access keys* / *Deploy keys* лише на читання. Не підключайтеся як `root`, краще під користувачем-власником сайту.

## Де що зберігається

| Що | Де |
|---|---|
| Налаштування | `~/Library/Application Support/Deployer/projects.json` |
| Секрети | Keychain, сервіс `Deployer` |
| Журнал застосунку | `~/Library/Logs/Deployer.log` |
| Історія деплоїв | `~/Library/Application Support/Deployer/history.log` (Мак), `~/deploy/history.log` (сервер) |
| Робочі копії й бекапи БД на сервері | `~/deploy/` SSH-користувача |

## Переклади

Ключами перекладу є англійські рядки в коді. Щоб додати мову, скопіюйте `src/locales/uk.json` у `src/locales/<код>.json`, перекладіть значення і додайте код у `LANGS` в `src/app.py` та в перемикач мов у `src/index.html`. Pull request-и вітаються.
