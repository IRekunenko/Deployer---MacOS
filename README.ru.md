# ⚡ Deployer для macOS

[English](README.md) · [Українська](README.uk.md) · **Русский**

**Коммит, пуш и деплой ваших проектов на собственные серверы в один клик: нативное приложение для macOS, без настройки CI/CD и без FTP.**

Создано для соло-разработчиков, фрилансеров и **вайбкодеров**, которые пишут код с Claude Code, Cursor, Copilot или ChatGPT и хотят просто и безопасно выложить его на сервер, не разбираясь в GitHub Actions, Jenkins или Docker.

Если вы до сих пор заливаете папки через FileZilla и правите базу в phpMyAdmin, Deployer заменит это на повторяемый и безопасный процесс:

> пишете код → **Коммит** → **Пуш** в Bitbucket / GitHub → **Деплой** на DEV → проверка → **Деплой** на PROD

## Возможности

- **Коммит и пуш** из простого окна: в один или несколько Git-сервисов одновременно (Bitbucket, GitHub, GitLab, Gitea / свой сервер).
- **Деплой в один клик** по SSH в отдельные окружения (DEV, STAGE, PROD…), у каждого свой сервер, папка и ветка.
- **Предпросмотр**: видно, какие именно коммиты и файлы изменятся и какие файлы будут удалены.
- **Безопасный прод**: только коммиты, которые уже есть в `main`, и подтверждение вводом названия окружения.
- **Бэкап базы данных** (`mysqldump`) перед каждым деплоем, плюс команда после деплоя для миграций, очистки кэша, `composer install`…
- **Откат**: деплой любого предыдущего коммита.
- **На сервер попадает только то, что есть в Git**: никаких случайных локальных файлов, `.env` или `.DS_Store` на проде.
- **Список «не трогать»**: конфиги, загрузки и кэш на сервере не перезаписываются и не удаляются.
- **Секреты в Keychain macOS**: пароли SSH, ключей и БД никогда не попадают в файл настроек.
- Поддерживаются **SSH-ключи с паролем** и **вход по паролю**; запрос появляется в окне приложения.
- **Один общий Git-ключ** для всех серверов: передаётся на сервер только на время деплоя и там не хранится.
- **На сервер ничего не нужно устанавливать**: достаточно SSH, `git` и `rsync`. Отлично работает с HestiaCP, хостингом с SSH, VPS, серверами Ubuntu / Debian.
- **Нативное приложение macOS** с иконкой в Dock, меню и горячими клавишами. Интерфейс **на английском, украинском и русском**.

## Как это работает

```
Mac (Deployer)                     Git-сервис                     Сервер
──────────────                     ──────────                     ──────
Коммит ──► Пуш ──────────────────► Bitbucket / GitHub / …
Деплой ──► SSH ──────────────────────────────────────────────────► git fetch (из Git-сервиса)
                                                                   бэкап БД → rsync в папку сайта
                                                                   → команда после деплоя
```

## Скачать

Скачайте последний **`Deployer-x.y.z-macOS.zip`** из [Releases](https://github.com/IRekunenko/Deployer---MacOS/releases/latest), распакуйте и перенесите **Deployer.app** в «Программы». Универсальная сборка: Apple Silicon и Intel.

- Deployer использует системные `python3` и `git`, поэтому нужны Xcode Command Line Tools: `xcode-select --install`.
- Приложение не нотаризовано Apple, поэтому macOS заблокирует первый запуск. Откройте *Системные настройки → Конфиденциальность и безопасность* и нажмите **Всё равно открыть**, или выполните:
  ```bash
  xattr -dr com.apple.quarantine /Applications/Deployer.app
  ```

## Требования

- macOS 12 или новее
- Xcode Command Line Tools (`xcode-select --install`): дают `git`, `python3` и `swiftc`
- На сервере: доступ по SSH, `git`, `rsync` (и `mysqldump` для бэкапов БД)

## Сборка из исходного кода

```bash
git clone https://github.com/IRekunenko/Deployer---MacOS.git
cd Deployer---MacOS
./build_app.sh --install
```

Команда собирает `Deployer.app` и устанавливает его в «Программы». Чтобы обновить, запустите её ещё раз.
Без `--install` приложение собирается в папку `dist/`.

## Быстрый старт

1. **⎇ Git**: проверьте ваши Git-сервисы (Bitbucket и GitHub уже добавлены; при необходимости добавьте GitLab или свой сервер). Создайте **общий Git-ключ** и добавьте его публичную часть в *Access keys* / *Deploy keys* репозиториев.
2. **🖥 Серверы**: добавьте сервер (IP, порт, пользователь) и выберите SSH-ключ или вход по логину и паролю. Добавьте публичный ключ Mac на сервер (например, HestiaCP: *пользователь → SSH Keys*). Нажмите **Проверить подключение**.
3. **＋ Проект**: выберите локальную папку проекта, отметьте, в какие репозитории пушить и откуда сервер забирает код, настройте окружения (сервер, папка сайта, ветка, файлы «не трогать», при желании БД).
4. Пользуйтесь кнопками **Коммит**, **Пуш**, **Проверить**, **Что изменится?** и **🚀 Деплой**.

> Перед первым деплоем нажмите **Что изменится?** и просмотрите список удалений: всё, что есть только на сервере (конфиги, загрузки, кэш…), нужно добавить в «Не трогать на сервере».

## Безопасность

- Пароли хранятся **только в Keychain macOS**. В файле настроек секретов нет.
- Секреты передаются на сервер через stdin SSH-сессии, а не в командной строке, поэтому их не видно в списке процессов сервера. Временные файлы создаются с правами `600` и удаляются после завершения.
- Локальный веб-интерфейс слушает только `127.0.0.1` и отклоняет запросы с других сайтов.
- Для общего Git-ключа используйте *Access keys* / *Deploy keys* только на чтение. Не подключайтесь как `root`, лучше под пользователем-владельцем сайта.

## Где что хранится

| Что | Где |
|---|---|
| Настройки | `~/Library/Application Support/Deployer/projects.json` |
| Секреты | Keychain, сервис `Deployer` |
| Журнал приложения | `~/Library/Logs/Deployer.log` |
| История деплоев | `~/Library/Application Support/Deployer/history.log` (Mac), `~/deploy/history.log` (сервер) |
| Рабочие копии и бэкапы БД на сервере | `~/deploy/` SSH-пользователя |

## Переводы

Ключами перевода служат английские строки в коде. Чтобы добавить язык, скопируйте `src/locales/uk.json` в `src/locales/<код>.json`, переведите значения и добавьте код в `LANGS` в `src/app.py` и в переключатель языков в `src/index.html`. Pull request-ы приветствуются.
